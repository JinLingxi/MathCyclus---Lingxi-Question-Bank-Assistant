# 试卷目录与录入流程

> 目标：把 2000–2026 的卷子，以及后续新增考试体系，统一到一套可维护的目录里。  
> 作用：让前端、脚本、AI 录入都按同一标准对表入座，减少临时命名和人工猜测。

## 1. 设计目标

- 统一高考 `G` 卷、新高考卷、地方卷、新领军、强基计划、大学自招等考试体系。
- 已收录卷子必须复用标准名，不允许前端或脚本自由命名。
- 未收录卷子先进入待确认状态，再人工确认写入主表。
- 题目只继承卷级信息，题级只处理题号、小题、题型、题干和图片等差异。

## 2. 建议的数据层

### 2.1 考试体系层

用于描述“大类”：

- 高考
- 新高考
- 地方卷
- 新领军
- 强基计划
- 大学自招
- 其他

### 2.2 试卷目录主表

建议字段：

- `paper_standard_id`
- `exam_family`
- `year`
- `region`
- `track`
- `paper_series`
- `paper_name`
- `source_name`
- `status`
- `sort_order`

### 2.3 别名表

用于保留历史叫法和原始文件名：

- `paper_alias_id`
- `paper_standard_id`
- `alias_name`
- `alias_type`
- `source`
- `note`

### 2.4 录入绑定表

用于把题目挂到标准卷：

- `question_id`
- `paper_standard_id`
- `question_number`
- `sub_number`
- `binding_status`

## 3. 录入流程

### 3.1 已收录卷

1. 识别卷信息。
2. 命中目录表。
3. 直接套用标准卷信息。
4. 题目批量继承，必要时只改例外题。

### 3.2 未收录卷

1. 识别出候选卷信息。
2. 生成临时标准名。
3. 进入待确认状态。
4. 人工确认后写入主表。
5. 后续同类卷复用该标准名。

### 3.3 UI 交互原则

- 不要每题弹窗。
- 只在“整卷未收录”时弹一次卷确认面板。
- 单题录入时，卷信息尽量由上层继承。
- 批量录入时，确认一次后批量套用。

## 4. 命名原则

- 标准名优先。
- 历史别名保留。
- 原始文件名保留为溯源信息。
- 文理、新高考、地方卷差异由目录表显式表达。
- 同一卷的历史叫法不要散落在代码里。

## 5. 你实际要怎么填

你以后补这个文件时，按“一个卷一行”来填，不要按题来填。

### 5.1 先填哪些字段

- `exam_family`：先选高考 / 新高考 / 地方卷 / 新领军 / 强基计划 / 大学自招。
- `year`：卷子年份。
- `region`：省份或地区。
- `track`：文科 / 理科 / 新高考 / 综合。
- `paper_series`：例如 `G`、`M` 等。
- `paper_name`：标准卷名。
- `source_name`：原始展示名。
- `status`：先用 `confirmed`、`pending`、`deprecated` 这类状态。

### 5.2 什么时候算确认

- 你确认“这就是这张卷”的时候，才写入主表。
- 如果一张卷还有文理、旧称、别名，就写到别名表。
- 如果还不确定，就先放待确认，不要硬写成正式名。

### 5.3 你审的时候看什么

- 年份对不对。
- 地区对不对。
- 文理 / 新高考类型对不对。
- 卷名是不是规范名。
- 这张卷以前有没有别名。

### 5.4 你不要做什么

- 不要把每道题单独当成卷来确认。
- 不要在聊天里临时起一个新名字就当正式名。
- 不要把题号、题目内容和卷名混在一起。
- 不要把历史别名覆盖掉。

### 5.5 最后落地原则

- 已存在的卷：直接复用。
- 没存在的卷：先待确认。
- 确认后：同类卷都跟着这个标准名走。
- 以后录入题目时，只需要先匹配卷，再挂题。

## 6. 建议落地顺序

1. 先做 2000–2026 的 `G` 卷目录表。
2. 再补地方卷和文理边界卷。
3. 再扩展新领军、强基计划、大学自招。
4. 最后把录入 UI 改成“目录匹配 + 待确认”模式。

## 7. 与现有项目关系

- 这份目录表将成为后续录入、去重、命名、检索的共同依据。
- `question_id` 仍然是题目主键。
- `legacy_id` 与旧 TeX 只作为历史映射保留。
- 目录表不替代题目表，只负责卷级标准化。

## 8. 当前已落地实现（2026-09-08）

- 已增加 `paper_standard_catalog`、`paper_alias`、`paper_match_review` 三张表。
- `0003_paper_catalog_matching.sql` 会把现有正式 `paper` 记录初始化为已确认标准名，并保留非空历史来源名为别名。
- 匹配规则按“年份 + 卷别 + 文理/新高考 + 试卷名”判断：精确命中可自动采用；相似候选必须人工点击采用；没有候选时必须点击确认新增。
- 单题、批量、同卷录入分别复用各自字段；同卷和批量按共同试卷确认一次并由草稿批量继承；同书录入不显示试卷匹配器。
- 匹配决策写入 `paper_match_review`，草稿 `extra_json` 保存 `paper_standard_id` 与决策信息。
- 正式草稿提交时优先使用已确认的标准名录记录；未应用迁移的旧数据库仍沿用原有试卷关联逻辑。

### 8.1 使用前提

1. 在“工具箱 → 本地维护与升级”应用数据库迁移，使正式库达到 schema version 3。
2. 首次迁移会从现有 `paper` 自动建立初始标准名录，不会上传或删除本地题目文件。
3. 以后遇到相似试卷，在录入页面选择候选并点击“采用此标准名”；遇到新卷，点击“确认新增为标准试卷”。
4. 只有确认后的标准卷才会进入正式 `paper` 关联，原始识别名仍保存在草稿和审核记录中。

5. 批量 TeX 内包含多张试卷时，系统按识别到的年份、卷别、文理/新高考和试卷名分组；每组单独匹配，但不按题目逐个弹窗。
