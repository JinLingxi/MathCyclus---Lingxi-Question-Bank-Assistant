# 题目 ID 规则

> 状态：第一版草案  
> 目标：为现有 `.tex` 题库迁移到 SQLite 主数据库提供稳定、可扩展、可反向映射的题目身份规则。

## 1. 基本原则

- 每道题必须拥有一个稳定 `question_id`。
- `question_id` 一旦生成，不应因文件移动、知识板块调整、试卷关系修改而改变。
- 当前 `.tex` 文件中的 `% ID` 作为 `legacy_id` 保留，但不再作为未来唯一主键。
- 文件路径作为 `legacy_file_path` 保留，用于追溯和反向导出。
- 新增题目以后也必须先分配 `question_id`，图片、试卷、教材、专题、修订记录都挂到它上面。

## 2. 第一版格式

推荐格式：

```text
Q000001
Q000002
Q000003
```

说明：

- 固定前缀 `Q` 表示题目。
- 后面使用 6 位数字，便于排序和人工识别。
- 当前 893 道题足够使用，未来增长到几十万道也可以扩展为 7 位或 8 位。

## 3. 现有题库迁移时的生成规则

第一版迁移采用稳定排序：

1. 扫描 `chapters/` 下所有正式题目 `.tex` 文件。
2. 排除 `content_*.tex` 汇总文件。
3. 排除 `相关图/` 下的辅助 TeX 源文件。
4. 按相对路径进行自然排序。
5. 依次分配 `Q000001`、`Q000002`、……

这样同一批文件在未移动前重复迁移会得到稳定结果。

## 4. 映射字段

迁移时至少保存：

| 字段 | 说明 |
| --- | --- |
| `question_id` | 新稳定 ID |
| `legacy_id` | 旧 `% ID` |
| `legacy_file_path` | 原 `.tex` 路径 |
| `content_hash` | 文件内容哈希 |
| `detected_chapter` | 从目录或 problem 参数识别的知识板块 |
| `detected_year` | 年份 |
| `detected_source` | 试卷名或来源 |
| `detected_question_number` | 题号 |
| `detected_topic` | 题目板块 |

## 5. 冲突处理

- 如果旧 `% ID` 重复，不影响新 `question_id` 生成，但必须写入报告。
- 如果文件路径重复，不允许迁移。
- 如果题目内容哈希重复，先不自动合并，只记录潜在重复题。
- 如果未来人工确认两道题是同题，应通过专门的“合并/关联”流程处理。

## 6. 后续新增题目的 ID 分配

数据库正式成为主存储后：

- 新题通过数据库服务分配下一个 `question_id`。
- 不允许页面层自行拼接 ID。
- 不允许用年份、题号、文件名作为 ID。
- 如果导入外部题库有外部 ID，应保存为 `external_id` 或 `legacy_id`，不能替代 `question_id`。
