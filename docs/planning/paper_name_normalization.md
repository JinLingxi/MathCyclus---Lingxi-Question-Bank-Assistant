# 试卷名称标准化规则

> 状态：第一版草案  
> 来源：`reports/paper_name_inventory_20260901.md` 与预览数据库中的 301 条试卷记录。  
> 目标：为未来试卷库、批量导入、全局浏览、组卷导出提供稳定的试卷命名和映射规则。

## 1. 为什么需要标准化

当前旧题库中，试卷信息主要来自文件名和 `\begin{problem}{年份}{类别}{试卷名}{题号}{板块}`。这种方式能工作，但存在几个问题：

- 同一试卷可能有多个写法。
- 文科、理科、新高考卷的标记方式不统一。
- 文件名中的简称不一定等于数据库中的标准名称。
- 批量导入时，源文件名和库中试卷名可能不完全一致。
- 未来要做试卷库和双向反查，必须有稳定 `paper_id` 和标准字段。

## 2. 试卷字段拆分

未来 `Paper` 应至少拆成：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `year` | 年份 | `2021` |
| `paper_series` | 卷别或来源大类 | `G`、`M`、`全国卷`、`新高考卷` |
| `track` | 文科/理科/新高考/综合 | `文科`、`理科`、`新高考`、`综合` |
| `paper_name` | 标准显示名 | `新高考I卷` |
| `source_name` | 原始来源名 | `新高考I卷` |
| `description` | 备注 | 可空 |

用户已确认试卷库应区分：

- 年份；
- 卷别；
- 文/理科/新高考；
- 试卷名称；
- 题号；
- 小题。

其中题号和小题属于 `PaperQuestion`，不属于 `Paper`。

## 3. 标准化目标

标准化不应破坏原始信息。建议保存两套名称：

1. `source_name`：原始写法，不改。
2. `paper_name`：标准写法，用于检索、展示、关系关联。

例如：

| 原始写法 | 标准写法 | track |
| --- | --- | --- |
| `全国卷I（理）` | `全国卷I` | `理科` |
| `全国卷I（文）` | `全国卷I` | `文科` |
| `新高考I卷` | `新高考I卷` | `新高考` |
| `上海春考卷` | `上海春考卷` | `综合` |

## 4. 初步规则

### 4.1 文理科识别

如果原始试卷名包含：

- `（文）`、`文科`：`track = 文科`
- `（理）`、`理科`：`track = 理科`
- `新高考`：`track = 新高考`

如果都不包含：

- 暂设为 `综合` 或空；
- 后续由映射表确认。

### 4.2 标准名清洗

标准名可以做轻量清洗：

- 去掉末尾 `（文）`、`（理）`；
- 保留 `新高考I卷`、`新课标I卷`、`全国甲卷`、`全国乙卷` 等核心名称；
- 不轻易把 `新高考I卷` 和 `新课标I卷` 合并；
- 不轻易把 `全国I卷` 和 `全国卷I` 合并，除非人工确认。

### 4.3 卷别字段

当前 `\begin{problem}` 第二个参数中常见 `G`、`M` 等。建议先保留为 `paper_series` 原始值。

未来可以再建立字典：

| code | 含义 |
| --- | --- |
| `G` | 高考真题 |
| `M` | 模拟题 |
| `W` | 未知或自定义卷 |
| `XK` | 可能表示校考/学科专题，需确认 |
| `XS` | 需确认 |
| `QJ` | 需确认 |
| `JS` | 需确认 |
| `WK` | 需确认 |

这些 code 当前不能乱解释，需要后续结合项目文件命名约定确认。

## 5. 映射表建议

后续应增加一张人工维护的映射表或 CSV：

```text
source_year,source_series,source_name,normalized_paper_name,track,note
2021,G,全国卷I（理）,全国卷I,理科,
2021,G,全国卷I（文）,全国卷I,文科,
2021,G,新高考I卷,新高考I卷,新高考,
```

建议文件：

- `db/seed/paper_name_mapping.csv`

作用：

- 批量导入前先对照映射表；
- 未匹配试卷不直接入库；
- 需要人工确认的试卷写入导入报告。

## 6. 不应自动做的事

第一版不建议自动合并：

- `全国I卷` 与 `全国卷I`；
- `新高考I卷` 与 `新课标I卷`；
- `全国甲卷` 与 `全国卷甲`；
- 同名但不同年份、不同省份的卷；
- 模拟卷中学校简称相似的卷。

这些都需要人工确认。

## 7. 下一步
