# 试卷命名标准化规划

> 状态：第二版规划草案。  
> 适用范围：SQLite 题库中的高考真题、地方卷、春考卷、未来批量录入试卷。  
> 当前原则：先审计、再人工确认、最后批量写库；不得直接用脚本静默改正式数据。

## 1. 标准化目标

旧题库里的试卷来源主要来自旧 TeX 文件名和 `\begin{problem}{年份}{类别}{试卷名称}{题号}{知识板块}`。这种方式能工作，但会带来几个长期问题：

- 同一张卷子存在多种写法，例如 `全国卷I`、`全国I卷`、`课标全国I卷`。
- 文科、理科、新高考、综合卷混在试卷名称里，筛选和反查不稳定。
- 同一道题出现在高考卷、教材、模考或专题中时，容易被误录为重复题。
- 未来做试卷库、书籍库、专题库和来源回溯时，需要稳定的结构化来源关系。

因此后续应把“显示名称”和“结构化字段”分开管理。

## 2. 推荐字段职责

当前 `paper` 与 `paper_question` 表已经基本具备试卷来源建模能力，建议按下列职责使用。

| 字段 | 所属表 | 作用 | 示例 |
| --- | --- | --- | --- |
| `year` | `paper` | 年份 | `2021` |
| `paper_series` | `paper` | 来源大类或旧 problem 第二参数 | `G` |
| `track` | `paper` | 文理/新高考/综合 | `文科`、`理科`、`新高考`、`综合` |
| `paper_name` | `paper` | 标准基础卷名，不建议夹带文理 | `全国I卷`、`新课标I卷`、`上海春考卷` |
| `source_name` | `paper` | 原始或展示来源名，可保留文理括号 | `全国I卷（理）` |
| `question_number` | `paper_question` | 题号 | `9` |
| `sub_number` | `paper_question` | 小题号或局部题号 | `1`、`a` |
| `display_order` | `paper_question` | 来源内展示顺序 | `9` |

推荐展示时组合为：

```text
{year} {source_name 或 paper_name} 第{question_number}{sub_number}题
```

推荐筛选和去重时使用：

```text
year + paper_series + track + paper_name + question_number + sub_number
```

## 3. 全国卷命名阶段规则

依据当前人工整理口径，全国卷体系建议先按年份分段标准化。

| 年份范围 | 标准口径 | 示例 |
| --- | --- | --- |
| 2005-2006 | `全国*卷` / 地方卷 | `全国I卷`、`全国II卷` |
| 2007-2013 | `新课标*卷`、`大纲*卷` / 地方卷 | `新课标I卷`、`大纲II卷` |
| 2014-2016 | `全国*卷` / 地方卷 | `全国I卷`、`全国II卷`、`全国III卷` |
| 2017-2019 | `新课标*卷` / 地方卷 | `新课标I卷`、`新课标II卷`、`新课标III卷` |
| 2020-2022 | `全国甲卷`、`全国乙卷`、`新高考*卷` / 地方卷 | `全国甲卷`、`新高考I卷` |
| 2023-2024 | `新课标*卷`，同时保留确有的 `全国甲卷/全国乙卷` | `新课标I卷`、`新课标II卷` |
| 2025 起 | `全国*卷` | `全国I卷`、`全国II卷` |

注意事项：

- `新高考I卷` 与 `新课标I卷` 不能自动合并。
- `全国甲卷/全国乙卷` 与 `全国I卷/全国II卷` 不能自动合并。
- `大纲II卷`、`大纲卷II` 可标准化为同一个 `大纲II卷`。
- `课标全国I卷`、`课标全国II卷` 在人工确认后通常可视为 `新课标I卷`、`新课标II卷`。

## 4. 文理与新高考规则

当前先采用保守规则：

- 2005 年以前的卷子暂不纳入本轮文理清洗，先保留原状。
- 试卷名含 `（文）`、`文科`：`track=文科`。
- 试卷名含 `（理）`、`理科`：`track=理科`。
- 试卷名含 `新高考`：`track=新高考`。
- 江苏卷默认 `track=综合`。
- 上海卷 2017 年以前需要确认 `文科/理科`，2017 年及以后暂按现有记录处理。
- 北京卷、天津卷 2020 年以前需要确认 `文科/理科`，2020 年及以后暂按现有记录处理。
- 2023 年以前的非新高考、非江苏正式高考卷，原则上应有 `文科/理科`；缺失时进入审计报告，不自动修改。

- 北京正式秋季高考卷不写“秋”字，统一使用 `北京卷（文）`、`北京卷（理）`；进入新高考后使用 `北京卷`。
- 北京春季高考卷必须显式写“春考”，统一使用 `北京春考卷（文）`、`北京春考卷（理）`。
- 不得使用 `北京卷（春文）`、`北京卷（春理）`、`北京卷（秋文）`、`北京卷（秋理）` 作为标准名。

## 5. 旧名称与别名策略

为了避免历史信息丢失，标准化不应简单覆盖原始来源。建议保留两层信息：

- `paper_name`：标准基础卷名，用于筛选、反查、来源关系判断。
- `source_name`：原始或展示来源名，用于前端展示和旧 TeX 兼容。

未来可以增加别名表：

```text
paper_alias_id, paper_id, alias_name, alias_kind, note
```

在正式表建立前，可继续使用 `db/seed/paper_name_mapping.csv` 作为人工维护映射表。

## 6. 当前清洗流程

试卷命名清洗应按以下顺序执行：

1. 运行只读审计脚本，生成当前试卷名称、建议标准名、建议 track、风险等级。
2. 人工查看高风险项，尤其是年份分段、文理缺失、同名不同卷、春考和地方特例。
3. 生成人工确认后的映射表，不直接覆盖旧表。
4. 批量更新 SQLite `paper` 表。
5. 如需要继续兼容旧 TeX，同步更新旧文件路径、`\begin{problem}` 头和 `legacy_question_map`。
6. 跑 `precommit_database_audit.py`、`audit_sqlite_legacy_bridge.py`、`audit_legacy_sqlite_consistency.py`。

## 7. 重复题处理原则

未来录入时遇到已有题目，不应直接新增重复题，也不应直接删除旧题。

| 情况 | 推荐处理 |
| --- | --- |
| 完全同题，同一题干/选项/答案/解析 | 复用原 `question_id`，只新增来源关系 |
| 同题出现在多张试卷、教材、专题 | 保留一个题目，多条来源关系 |
| 文理卷同一道题完全一致 | 原则上一个题目挂两个 `paper_question` 来源 |
| 题干相同但条件、图、选项或答案不同 | 新建题目，并建立 `question_equivalence` 变体关系 |
| 旧库已经重复录入 | 人工确认后合并关系、迁移知识点/答案/解析/图片，再删除弱副本 |

未来录入流程需要加入“重复候选检查”：

- 精确题干 hash。
- 归一化题干相似度。
- 同一年份同一来源同一题号冲突检查。
- 图片资源和答案解析差异提示。
- 人工选择：复用原题、新建变体、暂存待审。
