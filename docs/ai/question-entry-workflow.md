# 题目录入与 AI 识别流程

## 1. 统一入口

当前录入工作台的主要模式是：

- 批量试题录入：粘贴或导入多道 TeX，逐题生成草稿。
- 同卷试题录入：共享试卷来源，但每道题保留自己的题号和来源匹配结果。
- 同书试题录入：共享教材、页码和栏目等教材关系。
- PDF/图片识别：作为草稿生成能力接入录入流程，不直接入库。

## 2. 标准流程

```text
用户输入 TeX / 图片 / PDF
    ↓
来源元数据识别与人工确认
    ↓
云端 MinerU 版面解析（可选）或 PyMuPDF 回退
    ↓
按页、题号、坐标形成题目候选
    ↓
页面级 AI 输出题干、choices、答案、解析和分类草稿
    ↓
本地图片裁剪、图片绑定和 questionasset 草稿
    ↓
完全相同 / 高度相似 / 来源位置冲突检查
    ↓
人工逐题校订与二次审核
    ↓
正式题库写入、来源关系、图片关系、修订记录和导入记录
```

## 3. 来源处理

- 先确认年份、来源类型、卷别代码和试卷/教材/专题名称。
- AI 没识别到来源时，使用“未标记来源”，不要伪造年份或试卷名。
- 人工补充试卷名称后，再依据年份、卷别、文理/赛道和名称做模糊匹配。
- 同一批题如果每题识别出的来源不同，按题分组确认；没有可靠来源时不要强行继承错误的共同来源。

## 4. 草稿与审核

- `needs_review` 表示需要人工核对，不表示可以直接入库。
- `ready` 表示字段初检通过，仍需要人工最终确认。
- `approved` 绑定当前内容哈希，内容修改后必须撤销旧批准。
- `rejected` 或 `skip` 要保留理由和审核事件，保证后续可追溯。
- 缺答案或解析本身不是识别流程的硬阻断；缺题干、来源位置冲突或资源无法解析才需要重点拦截。

## 5. AI 边界

- PDF 识别的 AI 调用以页面或题目裁剪块为单位，不把整份 PDF 反复发送给模型。
- 大批量任务必须可查看进度、暂停、恢复、失败重试和最近任务状态。
- PDF 任务摘要必须保留输入文件哈希、解析器、模型、提示词指纹和识别器版本；逐题草稿还要保留实际识别 provenance，便于复现和追查。
