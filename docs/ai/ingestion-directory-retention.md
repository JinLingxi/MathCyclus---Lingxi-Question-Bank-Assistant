# 录题目录保留与引用审查

草稿图片迁入稳定存储、PDF 来源去重之后，data/imports 仍承载整题截图、原页截图、OCR 输出、任务候选、来源清单、导入载荷和历史修补依据。不能因为图片迁移已完成就删除对应年份目录。

## 审查入口

运行虚拟环境 Python：scripts/audit_ingestion_references.py --output reports/ingestion_reference_新的日期.json。

此工具只读主数据库与项目文本，不执行被扫描脚本，不修改业务数据，也不删除文件。它检查所有用户表的文本字段，包括 JSON 字符串、审核事件和修订记录，配合源码、文档、任务清单、TeX 等文件中的目录名称引用，生成各 data/imports 子目录的证据清单。

每个目录记录数据库引用、外部文件引用、内部文件引用、计数及前 40 条证据。历史审计/备份引用另作标记，不将其直接称为实时功能调用。超过 16 MiB 的文本载荷采用分块读取并处理块边界，避免大 JSON 因内存限制漏查；读取失败列入 scan_issues，避免把未检查误当无引用。

目录决策只有 retain_referenced（有字面引用，保留）和 manual_review_no_static_evidence（未找到静态引用，继续人工核对），所有目录的 delete_authorized 均为 false。相对路径拼接、动态路径、工作区外工具和未保存的 UI 状态无法穷尽，因此本工具不输出可自动删除名单。

## 体积解释

目录内 logical_bytes 是文件逻辑体积之和。已去重 PDF 的硬链接会出现在多个目录中，逻辑体积不能用来估算可再次释放的物理空间。同理，是否多个相同文件可以删除，仍取决于各路径的调用方。

## 后续调整条件

如某目录包含仍需使用的整题截图或原页，可另行设计稳定存储，并针对使用这些图片的审核页、来源回看和重试逐项验证；不能用简单字符串替换处理全部 JSON/TeX，也不能批量重置人工审核结论。保持原目录可回退直到验证通过。

维护脚本的历史引用不是移动/删除脚本的理由。需同时核对脚本间调用、相对路径和对应任务的重现需要，再给具体文件作归档决定。
