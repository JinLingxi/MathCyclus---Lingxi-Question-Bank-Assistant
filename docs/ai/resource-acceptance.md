# 整理后的资源验收与报告对比

## 统一入口

在项目根目录，用虚拟环境 Python 执行：

```powershell
.venv\Scripts\python.exe -m scripts.audit_resource_integrity --check-readability --baseline reports/resource_readability_audit_20261103.json --output reports/resource_acceptance_新的时间戳.json
```

先执行完整资源审计，再把当前问题逐项与指定基线比较，写入报告的 comparison 字段。原基线不覆盖、不自动接受新问题，不连接外部服务，不改变界面、题目、草稿、图片或审核状态。新输出路径必须尚不存在。

已有两份合格报告时，可独立运行模块 scripts.compare_resource_audits，使用 --baseline、--current、--output 指定文件，仅作报告比较，不重新扫描资源。

## 结果解释

- no_new_issues：两份报告共同覆盖的检查中没有新增问题，也没有计数下降或检查范围缩小。已有示例缺图、待生成任务仍会保留在原报告中；这不等于零问题或已人工批准。
- regression：新增了具体问题，按类别、题目/任务身份、字段、引用路径逐项比对，重复次数也参与比较。相同问题总数不能掩盖换了题目或文件的异常。
- review_required：没有新增缺失问题，但数据库记录、任务、路径检查计数减少，或基线执行了深度解码而本次没执行。需要解释业务变化或重新执行同范围检查，不自动改基线。

退出码 0 只对应 no_new_issues；新增异常或需复核时为 1。格式缺失、无效计数、问题数量与明细矛盾等报告不接受，命令失败，不伪造可比较结果。早期报告没有 readability_checked 范围字段时，需重新审计，不能默认当作已经做过深度检查。

## 验收边界

业务新增题目会显示计数增加，正常审批/删除会造成计数变化，报告只揭示变化，不擅自推断授权。计数相同不能证明每条记录未改；这仍需迁移清单、内容哈希和对应功能测试。跨报告的分类标准若有调整，也需要人工解读，不静默归并。

资源读取失败、脚本异常或扫描未完成时，不得使用旧报告声称当前工作区通过。基线应人工选择已完成验收的一份报告，并同时保留迁移、备份和 UI 验证依据。
